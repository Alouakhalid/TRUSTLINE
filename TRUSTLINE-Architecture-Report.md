## 1. Executive Architecture Summary

**TRUSTLINE** is a deterministic-first biomedical clinical decision support architecture designed for crewed space exploration missions. In operational deep-space environments (such as lunar sorties or transit to Mars), communication latency and intermittent blackout periods preclude real-time telemedicine from Earth.

### Architectural Invariants:
1. **Deterministic Safety Primacy:** Generative AI models (LLMs) are never given unilateral authority over clinical triage, red-line escalations, or biosensor validity. All risk classifications, emergency alert state machines, and sensor quality gating are executed via deterministic rule engines and statistical algorithms. LLMs are restricted to summarization, context explanation, and natural-language synthesis.
2. **Post-Generation Claim Auditing:** Every LLM output (whether generated by cloud or edge models) passes through deterministic claim validators (`ClaimGroundingValidator`, `ClinicalSynthesisValidator`, `RAGClaimValidator`). These validators use programmatic pattern-matching, citation cross-checking, and ground-truth boundary enforcement to detect forbidden diagnostic assertions (e.g., "myocardial infarction", "stroke") or ungrounded claims, replacing ungrounded output with deterministic rule-based text.
3. **Multi-Agent Orchestration via LangGraph:** The primary system orchestrator is a 10-node StateGraph compiled in LangGraph (`SupervisorWorkflowRunner`). It coordinates signal quality inspection, physiological feature modeling, medical literature retrieval, and multi-domain risk evaluation.
4. **Hybrid AI Router & Resilience Fallback:** A 3-state circuit breaker arbitrates inference between cloud APIs (Groq / Hugging Face via HTTPS) and local spacecraft edge models (`qwen2.5:7b-instruct` running on Ollama via `http://127.0.0.1:11434`), falling back to calling-service deterministic text when all models fail.
5. **Qualified Offline Resilience:** The core analytical pipeline (10-node LangGraph supervisor, DSP signal quality inspection, Core-14 feature extraction, HistGradientBoosting ML stress classification, 10-domain deterministic risk rules, and Ollama edge LLM fallback) is fully offline-resilient. However, multimodal auxiliary capabilities—specifically voice speech-to-text (`GroqVoiceService` via Whisper) and scanned document OCR (`MedicalDocumentExtractor` via Groq Vision)—strictly require cloud internet connectivity to Groq endpoints and cannot execute offline on the edge.

### Node 1: Intake (`intake_node`)
* **Source:** `ai-engine/agents/supervisor/workflow/nodes.py:25–55`
* **Input:** `SupervisorMultiAgentState` initialized from `SupervisorRequest`.
* **Execution:** Assigns tracking `workflow_id` (`WF-XXXXXXXX`), stamps UTC start timestamp, and records high-resolution start time via `time.perf_counter()`.
* **Output:** State with populated tracking metadata and duration metrics.

### Node 2: Input Validation (`input_validation_node`)
* **Source:** `ai-engine/agents/supervisor/workflow/nodes.py:57–113`
* **Input:** State containing astronaut and session identifiers, manifest path, and document paths.
* **Execution:** Audits `astronaut_id` and `session_id` against blank/dummy identifiers; performs path traversal sanitization on file paths; checks document file extensions against allowed set (`.pdf`, `.docx`, `.png`, `.jpg`, `.jpeg`, `.webp`).
* **Routing Decision:** Evaluated by `route_after_validation` (`ai-engine/agents/supervisor/workflow/router.py:4–10`):
  - *Nominal Path:* If no errors, routes to Node 3 (`sensor_quality_node`).
  - *Fast-Fail Bypass Path:* If errors are present, sets `workflow_status = "FAILED"` and routes directly to Node 7 (`evidence_validation_node`), skipping analytical nodes 3, 4, 5, and 6.

### Node 3: Sensor Quality Inspection (`sensor_quality_node`)
* **Source:** `ai-engine/agents/supervisor/workflow/nodes.py:115–142`
* **Adapter / Service:** `SensorQualityAdapter` (`ai-engine/agents/supervisor/adapters/sensor_quality_adapter.py:9–97`) invoking `QualityEngine` (`ai-engine/agents/sensor_quality/core/quality_engine.py:30–70`).
* **Configured Biosignals:** Verified against `ai-engine/agents/sensor_quality/data/input/astronaut_health_data.json` (WESAD chest bioharness standard):
  - `ECG`: 700.0 Hz (1 channel, mV)
  - `EDA`: 4.0 Hz (1 channel, uS)
  - `RESP`: 700.0 Hz (1 channel, mV)
  - `EMG`: 700.0 Hz (1 channel, mV)
  - `ACC`: 700.0 Hz (3 channels, g)
  - `TEMP`: 700.0 Hz (1 channel, C)
* **Execution:**
  1. `SignalLoader` (`ai-engine/agents/sensor_quality/ingestion/signal_loader.py:25–58`) memory-maps continuous binary arrays (`.npy` files).
  2. `QualityEngine` executes digital signal processing (DSP) checks: FFT spectral SNR analysis, sample integrity, timestamp continuity, flatline detection, and amplitude saturation.
  3. `QualityScorer` computes composite scores (0.0 to 1.0) and determines processing decisions: `PROCESS`, `PROCESS_WITH_WARNING`, or `REJECT`.
* **Output:** `SensorQualityReport` stored in `state["sensor_quality_result"]`.

### Node 4: Personal Health & Biometrics (`personal_health_node`)
* **Source:** `ai-engine/agents/supervisor/workflow/nodes.py:144–171`
* **Adapter / Service:** `PersonalHealthAdapter` (`ai-engine/agents/supervisor/adapters/personal_health_adapter.py:10–320`).
* **Verified Core-14 Biometric Features:** Defined in `ai-engine/agents/personal_health/schemas/physiological_features.py:78–94` (`Core14Features`):
  1. `hr_mean_bpm`: Mean heart rate (beats per minute)
  2. `hr_std_bpm`: Standard deviation of heart rate
  3. `hrv_rmssd_ms`: Root mean square of successive RR interval differences (ms)
  4. `hrv_sdnn_ms`: Standard deviation of NN intervals (ms)
  5. `eda_mean`: Mean skin conductance (microsiemens)
  6. `eda_std`: Standard deviation of skin conductance
  7. `eda_iqr`: Interquartile range of skin conductance
  8. `resp_rate_bpm`: Breathing rate (breaths per minute)
  9. `resp_std`: Respiration signal amplitude variability
  10. `temp_mean`: Mean skin temperature (°C)
  11. `temp_std`: Standard deviation of skin temperature
  12. `emg_rms`: Root mean square of surface electromyogram (mV)
  13. `acc_magnitude_mean`: Mean tri-axial acceleration magnitude (g)
  14. `acc_magnitude_std`: Standard deviation of tri-axial acceleration magnitude
* **Execution:**
  1. `SensorIntegrationService` (`ai-engine/agents/personal_health/services/sensor_integration_service.py:12–65`) ingests the session report from `QualityEngine` and the sensor manifest, filtering out invalid streams and constructing `sensor_context`.
  2. `FeatureExtractionService` (`ai-engine/agents/personal_health/services/feature_extraction_service.py:21–68`) extracts the Core-14 features.
  3. `PersonalBaselineInterface` (`ai-engine/agents/personal_health/services/baseline_interface.py:60–120`) computes Z-score deviations from normative pre-flight baselines.
  4. `MLInferenceService` (`ai-engine/agents/personal_health/services/ml_inference_service.py:30–56`) imputes, scales, and evaluates the pre-trained HistGradientBoosting model (`best_hist_gradient_boosting.pkl`) to predict acute stress probability.
  5. `EmergencyEscalationService` (`ai-engine/agents/personal_health/services/escalation_service.py:17–80`) evaluates immediate critical biometrics and reported symptoms against red-line safety thresholds. If triggered, sets assessment status to `URGENT_ESCALATION`.
  6. **Generation ➔ Validation Flow:** `generate_flight_surgeon_synthesis()` (`ai-engine/agents/personal_health/agent/agent.py:80–131`) sends prompt to `HybridAIRouter` (task: `PERSONAL_HEALTH_SYNTHESIS`). The raw text is passed to `ClinicalSynthesisValidator.validate_synthesis()` (`ai-engine/agents/personal_health/services/synthesis_validator.py:26–294`), which audits assertions against ground truth (HRV RMSSD variance, fluid shift evidence). If invalid or if inference fails, `validator.generate_grounded_fallback()` supplies deterministic safe text.
* **Output:** `PersonalHealthAssessment` stored in `state["personal_health_result"]`.

### Node 5: Medical Knowledge Retrieval (`medical_rag_node`)
* **Source:** `ai-engine/agents/supervisor/workflow/nodes.py:173–278`
* **Service:** `MedicalKnowledgeRAGService` (`ai-engine/agents/personal_health/rag/service.py:34–255`).
* **Execution:**
  1. Formulates search query from observed symptoms, biometric deviations, and mission elapsed time (MET).
  2. `HybridMedicalRetriever` (`ai-engine/agents/personal_health/rag/retrievers.py:35–131`) executes an integrated privacy routine (lines 101–131) checking query text against confidential patterns and cross-astronaut ID leaks. If personal identifiers are queried, aborts with `ISOLATION_VIOLATION`.
  3. Performs sparse BM25 keyword matching combined with dense cosine vector similarity against curated aerospace medical collections (`mission_medical_protocols.json`, `space_health_research.json`).
  4. **Generation ➔ Validation Flow:** `GroundedMedicalGenerator.generate()` (`ai-engine/agents/personal_health/rag/generation.py:96–254`) queries `HybridAIRouter` (task: `MEDICAL_RAG_SYNTHESIS`). The response is audited by `RAGClaimValidator.audit_response()` (`ai-engine/agents/personal_health/rag/validators.py:15–120`) to verify the 5-part structure and passage citations. If router fails, deterministic fallback synthesis is constructed directly from retrieved excerpts.
* **Output:** `RAGGenerationResult` with citations stored in `state["medical_rag_result"]`.

### Node 6: Multi-Domain Risk Assessment (`risk_assessment_node`)
* **Source:** `ai-engine/agents/supervisor/workflow/nodes.py:280–307`
* **Adapter / Service:** `RiskAssessmentAdapter` (`ai-engine/agents/supervisor/adapters/risk_assessment_adapter.py:6–79`) invoking `RiskAssessmentAgent` (`ai-engine/agents/risk_assessment/agent/agent.py:19–263`).
* **Execution:**
  1. `EvidenceNormalizationService` unifies upstream outputs into standardized `NormalizedEvidenceItem` objects.
  2. `RiskEngine` (`ai-engine/agents/risk_assessment/services/risk_engine.py:44–250`) evaluates deterministic rules across **10 Aerospace Domains** (Cardiovascular, Radiation, Hypoxia, Sensory-Motor, Musculoskeletal, Fluid Shift, Thermoregulatory, Dehydration, Sleep/Fatigue, Psychological).
  3. `RiskEscalationService` (`ai-engine/agents/risk_assessment/services/escalation_service.py:15–105`) executes finite state machine determining escalation urgency (`NOMINAL`, `MONITOR`, `REVIEW_REQUIRED`, `ESCALATION_REQUIRED`).
  4. **Generation ➔ Validation Flow:** `LLMInterpretationService.generate_explanation()` (`ai-engine/agents/risk_assessment/services/llm_interpretation_service.py:13–185`) builds clinical prompt and calls `HybridAIRouter` (task: `RISK_ASSESSMENT_SYNTHESIS`). Raw text is passed to `ClaimGroundingValidator.validate_synthesis()` (`ai-engine/agents/risk_assessment/services/claim_grounding_validator.py:6–180`), which checks for forbidden diagnostic terms and ungrounded claims. If grounding fails or if router raises an error, `LLMInterpretationService._build_deterministic_fallback()` supplies deterministic rule explanation.
* **Output:** `RiskAssessmentOutput` stored in `state["risk_assessment_result"]`.

### Node 7: Cross-Agent Evidence Validation & Quarantine (`evidence_validation_node`)
* **Source:** `ai-engine/agents/supervisor/workflow/nodes.py:309–328`
* **Service:** `EvidenceRegistryService` (`ai-engine/agents/supervisor/services/evidence_registry_service.py:5–65`).
* **Execution:**
  1. Consolidates all evidence tokens across nodes 3, 4, 5, and 6.
  2. **Quarantine Enforcement:** If a sensor was marked `INVALID` by DSP inspection, all derived features (e.g., `EV-PHY-HR-MEAN`, `EV-PHY-HRV-RMSSD`) are flagged with `is_quarantined = True`.
  3. Prohibits quarantined evidence from triggering high or critical alerts.
* **Output:** Audited evidence list stored in `state["evidence_registry"]`.

### Node 8: Final Synthesis & Contract Assembly (`final_synthesis_node`)
* **Source:** `ai-engine/agents/supervisor/workflow/nodes.py:330–566`
* **Service:** `AstronautCommunicationService` (`ai-engine/agents/supervisor/services/astronaut_communication_service.py`).
* **Execution:**
  1. Compiles the complete `FinalSupervisorAssessment` schema.
  2. Calculates wall-clock timing breakdowns across all nodes, measuring supervisor framework overhead vs. subagent computation times.
  3. Formulates tailored, non-alarmist natural-language clinical advice for the crew member.
* **Output:** Contractual assessment dictionary in `state["final_assessment"]` and advisory text in `state["final_response"]`.

### Node 9: Persistence (`persistence_node`)
* **Source:** `ai-engine/agents/supervisor/workflow/nodes.py:568–601`
* **Service:** `PersistenceService` (`ai-engine/agents/supervisor/services/persistence_service.py:9–85`).
* **Execution:**
  1. Opens connection to local SQLite store (`data/trustline_edge.db`).
  2. Executes `CREATE TABLE IF NOT EXISTS supervisor_assessments (...)`.
  3. Writes/updates session record with serialized JSON payload.
  4. Exports complete assessment JSON file exclusively to `data/output/final_supervisor_assessment.json`.
* **Output:** Database transaction status and disk artifact path.

### Node 10: Final Response & Completion (`final_response_node`)
* **Source:** `ai-engine/agents/supervisor/workflow/nodes.py:603–647`
* **Execution:** Stamps final completion timestamp, finalizes total elapsed runtime, seals state, and transitions to LangGraph `END`.
* **Output Delivery:** Returns completed `result_state` to `run_supervisor_cli()` in `ai-engine/agents/supervisor/main.py:65–103`, which prints formatted ASCII mission summary, agent status table, execution latency breakdown, and astronaut-facing advisory text to `sys.stdout`.

### Execution Semantics:
- **Sequential In-Process Execution:** Execution runs in a single process. CrewAI code exists in agent directories (`crewai_tools.py`, `agent.py`) but is **not** called by the Supervisor workflow.
- **Node Exception Degradation:** If an analytical node (3–6) throws an unhandled exception, it is caught in the adapter, marked `status = FAILED`, logged in `state["errors"]`, and execution continues to the next node.
- **CLI Linear Return Sequence:** The workflow terminates at `END`, returning `result_state` back to `run_supervisor_cli()` which handles formatted terminal output without looping back or re-triggering the workflow.

## 🛡️ 8. Failure Handling & Exception Paths

1. **Input Validation Failures:** Handled in `ai-engine/agents/supervisor/workflow/nodes.py:97–105`. Errors populate `state["errors"]`. The conditional router `ai-engine/agents/supervisor/workflow/router.py:4–10` bypasses nodes 3–6, landing directly in `evidence_validation_node`. The workflow completes with status `FAILED` and exit code `1`.
2. **DSP Sensor Gating & Corrupted Signals:** Handled in `ai-engine/agents/sensor_quality/core/quality_scoring.py:40–80`. If a sensor exhibits excessive noise, clipping, or flatlines, it is marked `INVALID`. In Node 4, `SensorIntegrationService` drops the invalid stream from downstream feature extraction. In Node 7, `EvidenceRegistryService` flags all downstream features derived from that channel with `is_quarantined = True`, preventing false alarms.
3. **Medical Knowledge RAG Exceptions:** Handled in `ai-engine/agents/supervisor/workflow/nodes.py:241–254`. If the vector store or retrieval engine throws an unhandled exception, it is caught in a `try...except` block, logging `retrieval_status = "SERVICE_ERROR"` and allowing downstream risk assessment to proceed without crashing.
4. **Hybrid AI Provider Cascade & Circuit Breaker:** Handled in `ai-engine/hybrid_ai/router.py:48–193` and `ai-engine/hybrid_ai/circuit_breaker.py:13–89`:
   - **Policy Check:** `CapabilityRegistry.get_policy()` immediately executes deterministic text for `DETERMINISTIC_OFFLINE` tasks (returning immediate `ProviderResponse` to the caller) or raises `TaskNotEligibleError` for `UNAVAILABLE` tasks.
   - **Mode Check:** If `AI_ROUTER_MODE == "LOCAL_ONLY"`, cloud inference is entirely bypassed and routes directly to the local edge model check.
   - **Cloud Stage:** If mode allows cloud and the circuit breaker is `CLOSED` or `HALF_OPEN`:
     - If text task and Hugging Face is configured (`hf_provider.is_configured()`), attempts `meta-llama/Llama-3.1-8B-Instruct`. If it fails, cascades to Groq Cloud.
     - Else, attempts Groq Cloud (`llama-3.3-70b-versatile`). On success, resets circuit breaker (`record_success()`). On failure, records failure (`record_failure()`), which trips circuit breaker to `OPEN` after 3 consecutive failures (30-second reset window).
   - **Local Fallback Stage:** If cloud fails, is bypassed (`LOCAL_ONLY`), or circuit breaker is `OPEN`:
     - Checks `CapabilityRegistry.is_local_eligible()`. If task is `CLOUD_ONLY` (e.g. OCR, Voice), raises `TaskNotEligibleError` (local execution is prohibited).
     - If local eligible, routes to `OllamaProvider` (`qwen2.5:7b-instruct` on `http://127.0.0.1:11434`), tagging response `is_fallback = True`.
   - **Calling-Service Deterministic Fallback:** If Ollama also fails, `HybridAIRouter` raises `ProviderUnavailableError`. Calling services catch this exception and execute their deterministic rule fallback:
     - *Personal Health:* `ClinicalSynthesisValidator.generate_grounded_fallback()` generates safe synthesis bound to numerical ground truth.
     - *Medical RAG:* `GroundedMedicalGenerator` constructs structured answer directly from retrieved passage excerpts.
     - *Risk Assessment:* `LLMInterpretationService._build_deterministic_fallback()` generates structured clinical risk explanation based purely on triggered deterministic rules.
   - **Post-Generation Claim Rejection:** If an LLM succeeds but fails claim grounding or validation audits, the calling service discards the ungrounded text and substitutes the deterministic fallback text.
5. **Database Transaction Failures:** Handled in `ai-engine/agents/supervisor/services/persistence_service.py:43–45`. If the SQLite write encounters a disk lock or I/O error, a warning is recorded and file-based JSON serialization is attempted. `workflow_status` is downgraded to `PARTIALLY_COMPLETED`.

## ⚠️ 12. Architecture Gaps and Limitations

1. **Absence of Service Gateway for Workflow:** The 10-node multi-agent supervisor workflow cannot currently be invoked over HTTP or WebSocket; it can only be executed via the CLI (`python -m supervisor.main`) or direct Python import (`SupervisorWorkflowRunner`).
2. **API Authentication Deficit:** The FastAPI document review service in `ai-engine/agents/personal_health/api/document_router.py` has no authentication or authorization checks. Any client on the network can upload, process, or confirm medical records.
3. **Single-Threaded Execution:** LangGraph subagents execute sequentially in a single process thread; asynchronous concurrency is not utilized across subagents.
4. **Cloud Dependency for Voice Recognition:** Voice audio processing is exclusively dependent on the external Groq Whisper API (`GroqVoiceService`). When disconnected from cloud connectivity, voice input cannot be transcribed locally.
